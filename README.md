# brain

`harangon/drbrain` 볼트를 Notion처럼 보고 편집하는 단일 페이지(`index.html`). 서버 없음, GitHub Contents API 직접 호출. PWA로 홈 화면 설치 가능.

## 구조 — 속성이 기준, 폴더는 자동
종류(`type`)는 노트와 프로젝트 둘뿐이다. 폴더는 종류와 보관 여부에서 정해지고, 사람이 폴더를 고르지 않는다.

| type | 폴더 | 프로젝트(`project: "[[제목]]"`) | 상태(`status`) |
| --- | --- | --- | --- |
| note | `20_Notes` | 선택 ("프로젝트 없음" 가능) | 비어 있음 → done |
| project | `10_Projects` | 자기 자신 | active · paused · done |

- **할 일은 종류가 아니라 노트의 상태다.** 날짜가 있거나(`due`), 할 일로 표시했거나(`todo: true`), 완료한(`status: done`) 노트가 할 일이다. 할 일 탭은 이런 노트를 모아 보여 주고, 노트 탭에는 할 일이 아닌 노트만 나온다
- 보관은 `archived: true` → `90_Archive`. 상태는 그대로 남는다
- 종류나 보관이 바뀌면 온라인일 때 바로 폴더를 옮기고, 불러올 때도 안 맞는 파일을 맞춘다. 옛 폴더(`00_Inbox`, `01_Daily`, `11_Todos`, `20_Cards`, `20_Areas`, `30_Resources`, `40_Notes`, `50_MOC`)의 파일은 노트로 보고 `20_Notes`로 옮긴다. 옛 `type: todo`·`type: card`는 저장할 때 `type: note`(할 일이던 것은 + `todo: true`)가 된다
- 파일 이름 = 제목에서 못 쓰는 문자만 뺀 것. 화면에는 원래 제목(`# 제목`). 제목을 바꾸면 파일 이름도 바뀌고, 겹치면 날짜를 붙인다
- `suggest-project`, `suggest-label` 속성(볼트의 `/inbox`가 적음)은 "AI 제안" 칩으로 보이고, 누르면 적용된다

## 사용
- 첫 실행: ⚙ → 저장소 `harangon/drbrain`, 브랜치 `main`, Fine-grained 토큰(Contents 읽기·쓰기). 토큰은 브라우저 localStorage에만 저장
- 탭: 노트(표 / 보드 / 갤러리, 할 일이 아닌 노트) · 프로젝트(보드에서 노트·할 일을 만들고 옮김) · 할 일(날짜·체크가 있는 것 모아 보기) · 일정
- 문서(폴더 트리 + 마크다운 편집기)는 머리줄 오른쪽 문서 아이콘으로 연다. 다시 누르면 보던 탭으로 돌아간다. 새로고침은 Ctrl+K → "새로고침 (캐시 비움)"
- 노트 탭: 할 일이 아닌 노트 목록. 옆 목록(폰은 위쪽 칩)에서 프로젝트·라벨을 눌러 거르고, 아래 "보관한 노트"를 펼쳐 되살린다. 동그란 체크는 완료, 네모 체크는 선택
- 프로젝트 탭(트렐로식): 맨 위 프로젝트 줄([전체] [프로젝트…] [+ 프로젝트])에서 바로 바꾸고 만든다. 프로젝트를 고르면 그 프로젝트의 보드가 화면을 채우고, 마지막에 본 프로젝트가 다음에도 열린다. "전체"는 상태별 목록(라벨 칩, 끝낸 프로젝트 포함). 목록의 줄을 끌어 순서를 바꾼다(프로젝트 노트의 `order`). 프로젝트 줄에는 진행 중인 것 중 목록 순서로 앞의 3개만 나오고 나머지는 "외 N개" → 전체 목록에서 고른다. 줄(리스트)은 직접 추가·이름 변경·순서 변경·삭제하고, 줄 아래 입력칸에 적고 Enter 로 추가하고("금요일 보고서"처럼 날짜를 적으면 할 일, 아니면 노트), 카드를 끌어 줄 사이로 옮기거나 순서를 바꾼다. "완료" 줄이 있으면 완료된 카드가 그 줄에 놓이고, 그 줄로 끌어 넣으면 완료가 된다. 제목이나 "상세"를 누르면 프로젝트 카드(설명·마감·라벨·활동)
- 보드 속성: 프로젝트 노트의 `lists: [할 일, 진행 중, 완료]`(없으면 이 기본값), 카드의 `list: 줄 이름`, 줄 안 순서 `order`
- 보관된 것: 노트 탭 "보관한 노트" · 프로젝트 탭 "끝낸 프로젝트" · 할 일 탭 "보관된 할 일"
- 빠른 메모(노트 탭) → `20_Notes/제목.md`. 옆 목록에서 고른 프로젝트·라벨을 물려받는다
- 보드: 상태 · 라벨 · 프로젝트로 묶고 드래그로 옮긴다. 같은 열 안 드래그는 순서(`order`)
- 표: 체크박스 선택 → 일괄 변경. 셀에서 바로 편집. 할 일은 왼쪽 체크가 완료
- 카드(노트·할 일·일정 탭에서 열 때): 제목 · 칩 · AI 제안 · 설명 · 체크리스트 · 첨부 · 연결 · 활동 · 동작. 프로젝트 카드에는 그 프로젝트의 할 일과 노트가 함께 나온다
- 노트 동작: "할 일로"(`todo: true`) / "할 일 해제"(날짜·완료도 지움), "프로젝트로 키우기". 프로젝트 끝내기는 완료 + 보관이고, 남은 할 일을 "프로젝트 없음"으로 돌릴지 함께 보관할지 묻는다
- 할 일 탭: 입력창(글 속 날짜 인식, 오늘 / 날짜… / 나중에, 프로젝트 선택) · 날짜 상자(Google 일정 + 그날 할 일) · 오늘·지연 · 이번 주 · 이후 · 나중에 · 완료. 오른쪽 프로젝트별 숫자는 완료/전체
- 일정: 월 달력에 Google 일정 + 마감·할 일. 날짜 선택 → 목록, 일정 클릭 → 수정, 칸 드래그 → 날짜 이동, 검색(전 기간), + 일정 / + 할 일
- 노트 링크: 문서 편집기와 카드 설명 편집에서 "링크" 버튼(노트 검색 → `[[제목]]` 삽입) 또는 `[[` 입력 후 목록에서 고르기
- Ctrl+K 팔레트, Ctrl+S 저장, Esc 닫기
- 오프라인: 저장·삭제·새 노트는 큐에 쌓였다가 자동 반영. 다른 기기가 먼저 바꾼 파일은 `(오프라인 사본)`으로 저장. 상단 "대기 N" 배지로 재시도·버리기. 폴더 옮기기와 파일 이름 바꾸기는 온라인에서만 되고, 못 한 것은 다음에 불러올 때나 볼트의 `/weekly`가 맞춘다

## Google 캘린더 연결 (Apps Script 프록시)
`gcal.gs`를 Google Apps Script 웹 앱으로 배포(실행 계정: 나, 액세스: 모든 사용자)하고, brain ⚙ → 연결에 웹 앱 URL과 KEY를 넣는다. 일정은 매번 Google에서 직접 읽고 쓰며 저장소에는 남지 않는다. 월 단위 5분 캐시, 오프라인이면 마지막 캐시를 "기준 시각"과 함께 표시. KEY는 브라우저에만 저장되고 요청 본문(POST)으로만 보낸다.

## 설정 파일
`drbrain/_scripts/brain.config.json` — `statuses`, `labels`, `props`(사용자 속성: id/name/type[text|number|date|select|checkbox]/options). ⚙ → 상태 · 라벨 · 속성에서 편집하면 커밋됨. 볼트의 `CLAUDE.md`가 이 파일을 참조.

## 프론트매터 규약
- `label`: 하나면 `label: work`, 여럿이면 `label: [read, work]`
- `order`: 보드 수동 순서(숫자). 바꿔도 `updated`는 갱신 안 함
- Obsidian 블록 리스트(`related:` + `  - "[[x]]"`)도 읽고, 쓸 때는 `[...]`로 정규화. 중첩 맵은 지원 안 함(저장 시 사라짐)

## 개발
- 코드 전부 `index.html` 하나. `sw.js`는 network-first 셸 캐시. 배포할 때 `sw.js`의 캐시 이름(`brain-shell-…`)을 바꾸면 열려 있는 앱에 "새 버전 — 새로고침" 띠가 뜬다
- 테스트: `python3 tests/build_mock.py && python3 tests/run.py [스크린샷 폴더]`. `tests/mock.js`가 GitHub API와 Apps Script를 메모리로 흉내 내고, Playwright(Chromium)로 화면 흐름을 돌린다
- 알려진 한계: 커밋 단위 파일 1개(폴더 옮기기는 커밋 2개) · 폴더 옮기기·첨부는 온라인 전용 · 미리보기는 기본 마크다운만
